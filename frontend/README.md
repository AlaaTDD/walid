# Sheet Nesting Frontend — Optimized Build

واجهة Flutter متكاملة مع FastAPI backend الخاص بـ Sheet Nesting.

## دورة العمل

1. اختيار صور PNG.
2. رفعها إلى `/upload` مع نفس الـDPI المختار في الإعدادات.
3. ربط كل صورة بـ`part_id` القادم من الـbackend بالترتيب، وليس باسم الملف.
4. حساب الـnesting عبر `/layout/compute/{job_id}` مع polling للـprogress.
5. عرض Proof Mode حقيقي للـlayout المحسوب من السيرفر.
6. دعم الشيت الجزئي: لو الشيت امتلأ، الترتيب الصالح يظل قابلًا للتصدير وتظهر الصور المتبقية بوضوح.
7. تأكيد التصدير عبر `/layout/confirm/{job_id}`.
8. تنزيل TIFF عبر `/download/{job_id}`؛ مسار `output_tiff_path` القادم من السيرفر لا يتم التعامل معه كأنه مسار محلي.
9. حفظ TIFF على الجهاز عبر `FilePicker.saveFile(bytes: ...)`.

## تحسينات الأداء والاعتمادية

- على desktop لا يتم تحميل كل الصور إلى RAM عند اختيارها؛ الرفع يستخدم المسار المحلي عبر `MultipartFile.fromPath`.
- على Web يتم الاحتفاظ ببيانات الصورة في الذاكرة لأن المتصفح لا يعطي مسار ملف محلي قابلًا للإرسال مباشرة.
- رفع الدفعات أصبح متسلسلًا لمنع إنشاء jobs متوازية عندما يختار المستخدم دفعتين بسرعة.
- duplicate filenames لا تسبب overwrite في الربط مع `part_id`.
- يتم إرسال `dpi` إلى `/upload` كما يطلب الـbackend، ثم يتم استخدام نفس القيمة في `/layout/compute`.
- تغيير DPI بعد رفع الصور يجبر المستخدم على إعادة الرفع بدل إنتاج قياسات خاطئة.
- progress polling لا يؤثر على صحة نتيجة الحساب؛ نتيجة `/layout/compute` هي المصدر الوحيد للحقيقة.
- إلغاء الحساب يستدعي `/layout/cancel/{job_id}`.
- Retry للتصدير لا يعيد `confirm` على job مؤكد؛ في حالة فشل تنزيل TIFF يتم توفير إعادة تنزيل مستقلة.
- تم التخلص من السحب المحلي الوهمي الذي كان يغير المعاينة فقط بينما التصدير يعتمد على layout السيرفر.
- `dart:io` معزول عن Web build.
- إعدادات الشيت وعنوان الـAPI محفوظة محليًا.

## عنوان الـAPI

الافتراضي:

- Desktop: `http://127.0.0.1:8000`
- Android Emulator: `http://10.0.2.2:8000`

على جهاز Android/iPhone حقيقي، ضع عنوان الجهاز الذي يشغّل FastAPI من **إعدادات التطبيق → عنوان الـAPI**.

## تشغيل

```bash
flutter pub get
flutter run
```

ويجب تشغيل الـbackend على:

```text
http://127.0.0.1:8000
```

أو العنوان الذي تحدده من الإعدادات.
